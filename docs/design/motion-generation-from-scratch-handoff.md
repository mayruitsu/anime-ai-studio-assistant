# 引き継ぎ資料：自前モーション生成モデルの開発（新テーマ）

作成日: 2026-09-09

## 背景・動機

`anime-ai-studio-assistant/motion-api`は現在、テキストから動きを生成するAIとして**MDM（Motion Diffusion Model）**を使っている。しかしMDMの学習データ（HumanML3D、由来はAMASS）のライセンスは、**「このデータを使ってニューラルネットワーク等を学習すること自体を商用目的で行うこと」を明確に禁止**している（個人・非営利利用は問題ない）。

ユーザーは以下の理由から、MDMに代わる「完全に自前・クリーンな学習データによるモーション生成モデル」の開発に挑戦したいと考えている。

1. 将来的な商用利用の可能性を残しておきたい
2. アニメ制作では同じアニメーションの使い回しは避けたく、クリップライブラリ方式（既存の決まった動きを再生するだけ）ではなく、**本当の意味で自然言語から独自の動きを生成できる仕組み**が欲しい
3. プロジェクト全体の一貫した方針（写真・イラスト・モーション等、学習データの出処が怪しいAIには頼らない）に合わせたい

## これまでの検討で分かっていること（重要、読んでから着手すること）

会話の中で複数の代替案を検討した結果、以下の結論に至っている。

### 代替データソース：CMU Graphics Lab Motion Capture Database

- **商用利用が明確に許可されている**（データそのものの再配布・転売のみ禁止）。BVH形式で公開、無料
- 約2500件のトライアル（歩く・走る・踊る・格闘・スポーツ動作など）を含む
- ただし**自然文の説明が付いていない**（基本的なカテゴリラベルのみ）。HumanML3Dのような(テキスト,動き)ペアではない
- 注意：AMASSはCMUを含む複数の生モーキャプデータセットをSMPL形式に統合したものだが、**AMASSとしての配布物自体が非商用限定ライセンス**。そのためAMASS経由ではなく、CMUの公式サイトから生データを取得し、自分でSMPL形式への変換を行う必要がある（「同じ実体のデータでも、入手経路によってライセンスが変わる」という点に注意）

### MDMのアーキテクチャ・コード自体は問題ない

- MDM（GuyTevet/motion-diffusion-model）のコードはMITライセンスで公開されている
- つまり**モデルの仕組み・学習コードを再利用すること自体は問題ない**。問題は学習に使うデータだけ

### 技術的な仕組みの正しい理解

MDMは拡散モデル（ランダムノイズから徐々に「それらしい動き」を作り出す生成モデル）であり、学習データの中のクリップをそのまま検索・再生する仕組みではない。つまり生成される動き自体は毎回新しく合成されるものだが、**「動きを生成する能力」自体がライセンス制限のあるデータの学習によって得られている**ため、出力が「新しい」ことはライセンス上の問題を解消しない。

### 期待値についての正直な見立て

CMUのデータ量（約2500件、説明文なし）は、HumanML3D（約15000件、人手による自然文説明付き）に比べて量・質ともに劣る。そのため、**再現できても本家MDMほどの表現力・自然さは期待しにくい**。これは技術力の問題ではなく、学習データの絶対的な差による構造的な限界。

## 推奨する進め方（段階的に検証しながら）

このプロジェクトでこれまで実績のある「小さく検証してから積み上げる」進め方を踏襲する。**いきなり学習に進まず、まずデータ準備パイプラインの品質を確認すること。**

### ステップ1：CMUモーキャプ→SMPL変換パイプラインの検証（最優先）

1. CMU Graphics Lab Motion Capture Database（`https://mocap.cs.cmu.edu/`）から、歩く・走る・手を振る等の基本動作のBVHファイルを少数取得
2. BVH形式からSMPL形式（関節角度θ）への変換処理を実装する。ゼロから書くか、MITライセンス等の互換性がある既存の変換ツール（要調査、例えば`bvh-python`等のBVHパーサー＋独自のリターゲティングロジック）を使うか検討する
3. 変換結果を`self-model-experiment/scripts/smpl_lbs.py`の`pose_and_skin`に通し、実際にSMPLメッシュが自然に動くか目視確認する（既存の`export_vrm.py`と組み合わせれば、VRMアバターに適用して確認することも可能）
4. **この段階で変換品質に問題がないか十分確認してから次に進む**（変換が不正確だと、その後の学習データ全体が汚染される）

### ステップ2：テンプレートによる自然文ラベルの自動生成

- `self-model-experiment/scripts/generate_skeleton_edit_dataset.py`や`anime-ai-studio-assistant/chat-api/generate_finetune_dataset.py`と同じ発想：CMUの動作カテゴリ（歩く・走る等）とメタデータ（速度、方向等が取れれば）から、テンプレートで自然文の説明を自動生成する
- 例：「歩く」というカテゴリのBVHファイルに対し、「歩く」「ゆっくり歩く」「前に歩く」等のバリエーションをテンプレートで生成

### ステップ3：小規模な拡散モデルの学習

- MDMの公開コード（MIT）をベースに、収集したデータ量に見合った小規模な設定で学習する
- 学習環境：WSL2にRTX 5070（VRAM約12.8GB）あり。OLMoのLoRAファインチューニングで実績あり（`chat-api/finetune_olmo.py`参照、ただし拡散モデルの学習は分類問題よりずっと重いため、データ量・モデルサイズの調整が必要になる見込み）

### ステップ4：VRMへの適用確認

- 学習したモデルの出力（SMPL関節角度の時系列）を、`anime-ai-studio-assistant/motion-api/export_vrm_pose.py`と同じ変換ロジックでVRMボーンのポーズに変換し、実際にVRMアバターが動くか確認する
